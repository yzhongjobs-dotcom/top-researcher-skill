# 三、方法设计（含快速验证与迭代）

**何时读：** 问题选定后设计或改造方法时，或者快速验证结果不理想、需要判断下一步时。

例子只用于说明，不是必须照做的规定；合适就用，不合适就回到判断标准。例子出处见[首轮逆向分析](../references/examples/first_round_reverse_analysis.md)：R 编号见 §2–3，Buchli、Kang、Xue、Dyck、Jin、Fu 和 R22 见 §7；新一轮逆向分析（顶刊在各阶段的实际做法、单篇画像、两两对比）见[参考资料](../references/README.md)。**进入本阶段时读 [references/stages/03_method.md](../references/stages/03_method.md)**：其中"怎么做"是顶刊作者在这一步的做法，"尺子"（底线与加分）用来自检，诊断表给出改法。通用反例见[anti_patterns](../references/anti_patterns.md)。

**核心目的：** 设计或改造出一套方法，要做到三点：
- 准确解决选定的问题；
- 在关键指标上胜过最强 baseline（如果有的话）；
- 达到顶刊的专业完整度。

贡献检查和初步验证都在这一步内进行。

**判断标准：**
- **改动对准瓶颈：** 每处改动都对应一个已定位的瓶颈，并能说清它为什么能消除这个瓶颈。
- **准确解决问题：** 每项主张的能力都有对应的机制和证据。
- **增量清楚：** 相对最接近的工作，讲得清继承了什么、改了什么、新增了什么能力。改动小也可以。
- **胜过最强 baseline：** 在暴露瓶颈的条件下胜过它，并有消融。旧方法已经足够的条件下持平是合理的；两难问题允许一端持平、另一端明显改善。
- **专业完整：** 模型、假设、执行接口齐全；问题最看重的性质有推导、定理或机理分析支撑。每个保证写清对象、条件和没保证的部分，能由结构直接保证的就由构造保证；解释条件或界的含义（怎样随参数变化、特例下是什么），是充分条件时承认它保守。

**怎么做：**
1. **写清目标能力和成功判据。** 方法要估计什么、决策什么、受哪些约束；在哪些指标上要胜过最强 baseline。
2. **定位最强已有方法的瓶颈。** 看它卡在哪个环节：表示、模型、可用信息、优化/训练，还是执行。
   - 改一个还是几个环节，按实际情况分析。
   - 没有问题的部分尽量继承。
3. **锚定主线，为瓶颈找机制。** 主线可以随认识调整。先判断机制属于本领域还是外域：在同一任务、同样条件下已经实现所需能力的，属于本领域。
   - **外域机制：** 迁移改造过来就有很强的创新性。先理解它的作用机制和成立条件，再做必要的改造，并讲清改了什么。判断一次重新表述好不好，看它换来了什么：现成的保证、闭式解，还是可在线求解。
   - **本领域已经实质覆盖了问题：** 不缩小增量，回到第二部分继续追问它的 failure。
   - **两边都没有合适的：** 自行设计。
   - **需要多个机制：** 每个只负责一项子能力，并处理好相互配合。
4. **先用推导或机理说明改动为什么有效，** 再投入大规模实验，避免靠调参碰运气。
5. **组合成完整方案。** 写清输入输出、模型和假设、求解或训练方式、执行接口，每部分对应第 1 步中的一项能力。不能用模块清单代替设计。
6. **让 AI 挑毛病，不让 AI 出 idea。** 给它近三年的相关文献，对照着挑几轮。
7. **快速验证，与最强 baseline 公平对比，然后迭代。**
   - 用保留任务关键困难的最小可信实验。
   - 调优过的简单方法用于诊断，不作为主基线。
   - 不如 baseline 时，查是哪一环没起作用（估计、决策还是执行），就改那一环。
   - baseline 本身已经足够好时，回到第二部分重新审视问题。

**可借鉴的做法：**
- **改动位置因问题而异：**
  - R13 重新设计能量函数的表示；
  - R01 让刚度和运动共享相位；
  - R03 用滤波历史构造含误差信息的残差；
  - Jin 同时改了模型表述、约束、求解和执行。
- **外域来源可以很远：**
  - 化工过程控制（Kang 的 IMC）；
  - 计算机图形学（Dyck 的离散微分几何）；
  - 数值数学（Xue 的张量列）；
  - 随机最优控制（Buchli 的 PI2）。
- **迁移时做一次重新表述，** 把本领域的问题改写成成熟工具能直接处理的形式：
  - Jin 把变阻抗律设计转成控制律设计，MPC/QP 才能用；
  - Buchli 把增益调度放进 DMP 参数，PI2 才能同时优化轨迹和增益；
  - Dyck 定义了曲面任务坐标，经典阻抗控制才能用于任意曲面。
- **迁移原理后，在本领域重新推导并给出保证：** R11 从代价函数出发，用 Lyapunov 方法推出更新律。
- **组合时先找出会冲突的地方，再设计分工去化解。** 这是组合方法和简单拼接的区别，可以对比 R12 和 R22。
- **理论集中保证问题最看重的性质：** 交互类论文常是稳定性或无源性；R19 没有理论，靠明确的物理成功率支撑。
- **检查能否把已有方法纳入为特例：** 能的话，增量最清楚（R13 的函数类包含已有的能量函数）。

**AI 犯过的错：**
- **用简单拼接代替设计：** 堆上策略库、后验规划等模块，却说不清它们怎样共同解决问题。
- **要求部件独有、全新：** 例如坚持某个借鉴来的求解器必须是独有贡献。
- **实际实现与方案名称不符：** 例如把原构想简化成另一种实现（如直接套一个强化学习算法），却仍按原方案名称下结论。
- **结论超出证据，或者反过来无限保护 idea。**
- **把更准的估计当成贡献：** 从信息到动作再到性能，这条链没有验证。
- **混淆理论对象和数值对象：** 把数值方程的根当成优质策略，把条件性的界当成实际保证。
