# 二、找真正值得研究的问题

**何时读：** 提出、修订或比较研究问题时，或者遇到强 prior、需要判断是否换题时。

例子只用于说明，不是必须照做的规定；合适就用，不合适就回到判断标准。例子出处见[首轮逆向分析](../references/examples/first_round_reverse_analysis.md)：R 编号见 §2–3，Buchli、Kang、Xue、Dyck、Jin、Fu 和 R22 见 §7；新一轮逆向分析（顶刊在各阶段的实际做法、单篇画像、两两对比）见[参考资料](../references/README.md)。**进入本阶段时读 [references/stages/02_problem.md](../references/stages/02_problem.md)**：其中"怎么做"是顶刊作者在这一步的做法，"尺子"（底线与加分）用来自检，诊断表给出改法。通用反例见[anti_patterns](../references/anti_patterns.md)。

**核心目的：** 找到一个值得做、也做得出来的研究问题。

**判断标准：** 任务需要的能力和最强方法能给的之间，有一个真实且重要的差距，同行能认出它确有必要研究（这就是领域的 taste）。同时还要满足三点：
- 尚未解决，或者解决得不够；
- 解决后有实质的科学增量；
- 能做出来，也能验证，问题大小合适。

**怎么做：**
1. **从两种来源找。**
   - **领域公认的难题：** 来自一篇文章，最好是几篇文章共同指出的问题。汇总它们的共性，再追问两点：为什么至今没解决（难点到底在哪）；已有的尝试做到了哪一步。
   - **没人明确提出、但普遍存在的 failure：** 从应用的真实需求、物理过程和第一性原理出发，对照主流方法依赖的假设，看几种方法是否在同一条件下都出问题。最好用推导或最小实验确认这个 failure 真实存在，并且影响任务表现。
2. **到前沿边界里找线索。** 线索来自第一部分标出的文献冲突、解释缺口和边界条件。顶刊样本中另外三种常见来源：两类文献的交叉处；前作（自己或他人）的具体失效或未解问题；任务或流程的结构对某个环节提出的要求。
3. **遇到强 prior 不避开，用苏格拉底式追问：**
   - 它解决了什么，在什么条件下成立？
   - 条件不成立时会怎样？
   - 作者没处理，是做不到还是没想到？
   - 这个问题解决了，会改变什么能力或认识？

   追问出的剩余痛点，往往就是更好的研究问题。
4. **表述成“具体任务 + 核心矛盾 + 希望改善的能力”。** 能力尽量定义成可测量的量。问题不能抽象到无法验证，不能小到只剩一个算法细节，也不能大到做不完。用显式假设划定范围，目标写成 2–4 条可检验的期望性质，每条后面都要有对应的方法和证据。顶刊常一次只推进一步：解决一个具体失效、去掉一个假设，或加入一个更真实的条件；警惕靠加模块扩大问题。
5. **产出候选问题，交给用户选定。** 每个候选写清痛点、文献依据、现有方法的解决程度、解决后的价值和主要风险。问题可以随认识加深优化，但不能偏离核心问题；实质换题由用户决定。

**可借鉴的做法（几种常见的差距形态，并不完整）：**
- **两难：** 两个都想要的性质，已有方法只能二选一或此消彼长。例如：
  - 稳定性与精度（R13）；
  - 精度与鲁棒性（Kang）；
  - 精度与柔顺（Jin）；
  - 泛化与最优（Xue）；
  - 可操作性与接触稳定（R12）。

  可以问：哪两个性质难以兼得？最强的方法分别站在哪一边？

  顶刊处理两难有三种形态，并写明理由：排序（一端作硬保证，另一端作优化目标）；把一端的负担转移给另一个部件；在两端之间自适应，或把两端纳入为特例。不要只在代价里给两端加权而不说明优先级。
- **存在性证明：** 人或其他系统已经能做到，机器人还做不到（R11、R01、Buchli）。
- **先定义能力，再据此设计指标：** 例如 R12 先定义可操作性和接触稳定性。
- **在方法之前展示失败：** 用一个最小例子或已有结果，说明不解决会怎样。

一个问题哪种形态都不像，只要满足判断标准就成立。不要为了套用某种形态去改问题。

**AI 犯过的错：**
- **过度防守、不断缩题：** 问题越缩越小，最后变得抽象又没意义。
- **渐进偏题：** 从原问题逐步滑向相邻、更容易做的问题（例如从“怎样更新控制”滑到“更新有多大价值”“整段资源规划”），原问题被暗中替换。
- **为了让某个算法能赢而缩题。**
- **把自己的机制预设成必要前提：** 例如写“必须先把两种来源分开”，但已有方法不分开也能处理。
- **稻草人式立题：** 例如写“已有几类方法各自必然失效”，证据并不支持。
