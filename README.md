# 顶级研究者的科研思维方式

本文件夹是一套通用的科研经验，与任何具体项目的 idea、实验和代码分开。目标是：agent 读完这些文件后，在选题、研究现状、问题凝练、方法设计、实验和写作上，能按顶会顶刊研究者的水平思考、判断和处理问题。

结构参照 skill 的渐进披露：

- **本文件**：总目标、判断依据、阶段表和总原则。每次都读。
- **[workflow/](workflow/)**：每个科研阶段的规则与经验。进入某阶段时只读对应文件。
- **[references/](references/README.md)**：逆向分析得到的参考资料，用来细化、校正和深入理解规则。遇到具体任务时按阶段文件的指引按需加载。

规则从参考资料中提炼，每条规则应能回查到实例；参考资料发现规则不对或不完整时，回头修改规则。

> **怎样使用**：和用户一起做研究，或评判、优化一个 idea 时，先读 [references/stages/README.md](references/stages/README.md) 的"用法 A（做研究）"或"用法 B（评判和优化）"，再按阶段读 `workflow/` 与对应的 `references/stages/` 文件。规则层写流程与判断，参考层写顶刊在每一步实际做到什么程度（来自 30 余篇顶会顶刊的逆向分析，每条可回查页码）。

## 一、目标与判断依据

目标是持续产出有实质科学贡献、证据足以参与顶刊竞争的论文。问题应具体重要，方法应专业完整、适合当前问题，并取得相对领域充分已有能力的实质进展；证据支持所声称的能力，条件、成本与边界准确。

**从具体顶会/顶刊论文理解方法和贡献，再用于判断。** 研究论文实际继承了什么、调整了什么、怎样形成有效方案、如何组织证据与贡献，不先凭空制定一套标准让论文和候选满足。样本中的实际设计提供参照，不构成统一录用清单；不设固定提升比例、全新组件数量、独有算法、庞大改动或定理数量要求。论文发表身份、流程完成和局部胜率均不能单独证明达标。

## 二、科研阶段：做法、产出与判断

进入某一阶段时，再读 [workflow/](workflow/) 中对应的文件（表中阶段名后的链接），其中写明该阶段的判断标准、具体做法、可借鉴的做法和常见错误。产出是帮助研究推进的具体内容，不要求每轮另写模板文档，也不设串行审批关卡。

| 阶段 | 做法 | 应形成的内容 | 这一阶段怎样判断 |
|---|---|---|---|
| **1．理解领域现状**（[详](workflow/01_literature.md)） | 围绕核心问题核读原文，理解强方法的机制、充分能力、条件与代价，持续补查关键疑问。最接近的工作要找全，检索不再出现新的直接近邻为止；外域相近机制记录作方法参考，不作为竞争者写进现状。 | 按能力组织的现状、直接近邻与可借鉴机制；明确原文事实和待核判断。 | 能准确说明已有方法实际能做什么及仍值得深入的地方；不只罗列论文或作者自述局限，不选择性取证。 |
| **2．凝练重要问题**（[详](workflow/02_problem.md)） | 从实际需求、目标冲突、已有能力边界和第一性原理深入追问；用苏格拉底式追问分析强方法仍有什么困难、为什么、能否改进。既研究公认难题，也寻找尚未清楚提出的重要问题。 | 具体任务、重要矛盾、希望改善的能力及其依据；允许作为可修订假设。 | 任务需要的能力与最强方法之间有真实、重要、同行能认出的差距；说明解决后改变什么能力或认识、已有解决程度及进一步研究价值；不因强工作存在退避，不为某算法能赢而缩题。 |
| **3．形成方法**（[详](workflow/03_method.md)） | 明确所需能力，沿成熟主线改进，或围绕问题自然组合、改造机制，必要时自行设计；主动研究本域与外域迁移，通过推导、实现和初步检验共同设计，同步检查贡献是否已被实质覆盖。先定位最强方法卡在哪个环节（表示、模型、信息、优化/训练、执行），改动对应瓶颈；外域迁移常靠一次重新表述，并在本领域重新推导。让 AI 对照近三年文献挑毛病，不让它出 idea。 | 少量有依据的完整候选：继承与调整、关键关系、输入输出、模型/假设、训练或求解、反馈与执行接口。 | 方案适合当前问题，组成部分协调，能解释所作调整为何可能有效及相对已有能力的进展；初期允许机制尚待验证，不要求部件全新或算法不可替代。 |
| **4．快速验证**（[详](workflow/03_method.md)） | 用保留关键任务困难的最小可信理论或实验，尽早比较充分调优的简单方法（用于诊断，不作主基线）及相关强方法，检查机制与实际收益。 | 能支持下一决定的结果、成本和失败范围；区分候选设想、实际实现及测试实例。 | 验证对象与主张对应，公平计入可得信息、训练/准备、计算和执行条件。声称性能更好却不如合理简单方法时，该性能主张尚未成立；不以一次简化实验裁决整套构想。 |
| **5．共同迭代问题与方法**（[详](workflow/03_method.md)） | 结合原文、推导和结果，判断应修实现、实验、机制、适用条件还是问题，主动提出并实现调整。 | 调整依据、影响层次、改进后的候选及下一项有决定作用的验证。 | 每轮增加方法有效性、问题价值或证据可信度；局部结果不越界，累计证据也能推动高层修订，不用“只是局部”无限保护 idea。 |
| **6．收敛贡献与完整证据**（[详](workflow/04_experiments.md)） | 围绕清晰、有分量的主贡献，补足相关理论、强对照、机制分析、泛化、成本及必要实物验证。正面对比最像自己的方法并讲清机理区别；指标用任务物理指标，不用方法自身代价。 | 与最接近工作的准确区别、完整可复核证据、适用条件与失败边界。 | 实质进展经得起强方法比较与替代解释检验；理论和实验各支持对应主张。方法构造、原型收益和最终论文竞争力分开判断。 |
| **7．组织论文与贡献表达**（[详](workflow/05_writing.md)） | 将实际改进组织到恰当的能力层次，清楚呈现问题、方法、创新性和证据；从早期同步梳理，随结果修订。 | 有说服力的问题叙述、方法逻辑、贡献陈述及实验论证，各部分相互支撑。 | 读者能理解为什么值得研究、具体做了什么、为何有价值、证据到哪里。包装准确体现真实进展，不将小改造夸成全新范式，也不因只列模块或公式而低估实际贡献。 |

各阶段交叉循环。问题和方法可在借鉴、推导、实验中共同成形，不要求先得到完美问题才设计算法，也不必先证明所有已有方法失败；不能一直调研、诊断而不提出并实现候选方案。初期用低成本验证推进有依据的设想，后期补齐贡献证据；不以终稿要求阻断探索，也不以初步结果宣布达标。仿真保留任务真实必要结构，不靠堆复杂度或制造条件让方法获胜。

**方法设计是主目标，对照实验服务于形成与改进方法。** 多候选分别设计、分别实验和判断；各自满足要求则保留，不满足则据具体失败继续优化。不能把补齐比较方法当作研究完成，也不能以融合或挑选局部结果代替各候选的实际证据。

**实验从研究问题和候选方法出发。** 先明确各候选要验证的能力，分别写出实际方法代码并完成对应仿真；具体论文提供可借鉴的实验做法。随后选择适合任务的比较算法，有则核准复现/任务适配并公平比较，没有合适对象则无需强行设置基线。不能反过来先选一个 MPC 或照搬论文任务，再让候选迎合它；也不因没有外部基线便声称方法已达顶刊水平。

## 三、方法形成与顶刊方法的实际尺度

**方法形成与成稿叙事是两个层次。** 成稿可以把方法写得像从问题自然推导出来；逆向分析还应拆出成熟基础、具体调整、适配关系和验证作用，学习可行的构造路径。不能仅凭公开成稿声称恢复了作者真实的发现顺序，也不能把会解释论文等同于会形成方法。

两种常见设计思路均应积极使用，可交叉，不是穷尽分类或强制路线：

- **沿成熟方法主线改进。** 深入理解其机制和当前问题，调整关键表示、模型、假设、信息、训练、优化或执行结构。改进可以来自理论分析、实验发现，或相关/不相关领域工作的启发与迁移。
- **围绕明确问题自然组合、改造方法。** 可以没有单一主线，但各部分应有具体任务作用和协调关系，形成专业、完整、有效的方案。通过设计解决相容性、信息传递或执行问题，不能用模块清单代替这些工作。

**借鉴正常，改进可以小。** 方法可以大量继承已有部件，关键调整也可以简洁。关注借鉴后具体做了什么、是否适合当前问题、连接是否专业、结果是否有效，以及相对最接近工作的实际进展。不因方法已有或改动不大否定价值，也不因做了迁移或拼合就认定创新成立。

**论文包装是研究工作的重要部分。** 把真实调整组织成清楚、有说服力的能力与贡献，准确说明其重要性，并安排对应证据。问题—方法—证据的叙述可在研究中共同打磨；呈现中说不清的地方，应反馈到设计和验证。贡献表述的强度与实际工作和证据对应。

具体参照见[首轮逆向分析 §2–4](references/examples/first_round_reverse_analysis.md)：R01 的共同相位小扩展、R13 的受约束表示、R12 的目标动力学分工、R11 的正向迁移、R19 的简洁残差结构、R21 的物理—可执行集合。例子用于理解尺度，不规定必选形式。

## 四、执行原则与防止重犯

- **保持核心问题连续，允许有依据地修订。** 已有问题和方法是可修订起点，已有候选不是必须保留的答案。实质换题说明依据、影响与可选方向，由用户取舍；题内探索主动推进，不反复求批，不逐渐漂移成抽象、过小或过大的题目。
- **深入强工作，主动寻找迁移机会。** 遇到本领域强工作，按能力和条件继续追问还能怎样改进；其他领域的成熟方法是设计资源。本域实质覆盖时修正贡献判断并继续深挖，不因算法名称或模块重合退避、缩题。
- **分开判断错误、方法成效和证据范围。** 对标准理解不足、过度防守、偏题或验证对象混淆应纠正；具体原型收益不足仍需实质改进，不归给未经证实的单一原因。区分原文、agent 归纳、假设和实测，重要判断可追溯，事实与数学不由预期决定。
- **依据阶段推进，保留准确边界。** 不确定性是候选关注点，不自动成为新题或永久门槛；区分基线、候选改动和被测实例。核清理论对象、数值近似、实际闭环及部署成本，避免局部结果扩大，也避免以局部性无限保护原方案。
- **自主推进，简洁记录。** 按需使用文献与工具，每轮说明问题和方法的变化、关键证据及下一决定；稳定认识写入规则，具体论文、实验和失败细节放在相应文件。新讨论先梳理建议，经用户确认再写入长期约束；已确认要求不反复请求批准。
- **仿真实验章节与顶刊写法对齐。** 2–4 个与研究问题对应的场景实验，每个按“目的—设置—结果表/图—结论”写，配少量代表性对照、一个消融和计算时间；不加多批重复测试等特殊做法。固定阻抗等固定参数对照按领域惯例取方法自身上下界两端，不以调到最优的固定参数方法作主基线。多个候选都要报告。不确定时先对照顶刊原文。（2026-10-22 用户确认）
- **汇报直接给结果。** 在对话中用中文直接给出具体数字、表格与结论，并说明所提方法相对基线如何、为什么；不只给文件链接。大规模运行前先说明额度消耗。（2026-10-22 用户确认）
- **汇报说清理解、工作与结果。** 用几句话具体说明如何理解研究问题及候选、实际改了/测了什么、结果是什么。提到比较须说明对象和为什么比较，给必要数字、范围和未完成内容；不用抽象计划代替实际工作。
