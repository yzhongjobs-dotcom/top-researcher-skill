# 阶段参考层：顶刊研究者在每个阶段怎么做、做到什么程度

本文件夹从真实的顶会顶刊逆向分析而来，目的是让 agent 成为**顶级研究者**：

- **会做**：能和用户一起，从头把一项研究做到顶刊水平，包括看清现状、找到值得做的问题、让方法从问题里长出来、设计能支撑主张的实验、把贡献放在恰当的层次；
- **会判断**：熟练掌握顶会顶刊的标准，能评判一个已有的 idea 或 section，并把它优化到顶刊水平。

写作另有 skill，不在这里。

五个阶段文件与规则层 [workflow/](../../workflow/) 一一对应。规则层写研究流程，本层写顶刊作者在每一步实际怎么做、做到什么程度：

| 文件 | 这一阶段做什么 |
|---|---|
| [01_literature.md](01_literature.md) | 看清最强方法做到哪里、为什么停下，找到真实的缺口 |
| [02_problem.md](02_problem.md) | 找到值得做的问题，并把它定准 |
| [03_method.md](03_method.md) | 让方法从问题里长出来，做到专业完整；含快速验证与迭代 |
| [04_experiments.md](04_experiments.md) | 从主张出发设计实验，让证据支撑主张 |
| [05_contribution.md](05_contribution.md) | 把贡献放在恰当的层次，强度与证据一致 |

每个阶段文件的结构相同：

1. **要回答的问题**；
2. **怎么做**（主体）：顶刊研究者在这一阶段的做法与招式，每一招附真实论文的例子，最后写出这一阶段应当产出什么；
3. **做到什么程度**（尺子）：
   - **底线**：几乎所有已发表的顶会顶刊样本都满足的，并点名例外；
   - **加分**：多数一档期刊样本具备、会议和短文常省略的；
4. **适用条件**：随论文类型、期刊文化的变化；
5. **自检与改进**：诊断表，即"症状 → 没达到哪条 → 怎样改 → 对照"；
6. **升级样板**：真实论文从前版到后版，这一阶段改了什么；
7. **锚点论文**。

---

## 一、用法 A：做研究（按阶段推进）

1. **定类型**：理论/方法型（贡献是通用的表示、机制、条件或保证），还是应用/问题驱动型（贡献是在具体任务中获得某种能力）。同一项工作只按一种类型选锚点和标准，避免"四不像"；如果其中有一条属于别的类型的主张（例如方法论文里声称"人更省力"），这条主张按它自己的证据要求配齐。
2. **每个阶段按"怎么做"推进**，得到该阶段的产出。
3. **每个阶段结束时用尺子自检**：底线必须满足；加分按目标档次争取。不满足的，用诊断表改。尺子来自已发表样本的共性：不满足底线几乎一定有问题，但满足全部条款不等于一定被接收，最终看贡献是否成立、是否重要。
4. **阶段之间检查闭环**（见第三节）：问题定下后，检查方法的改动是否对准问题里的机制原因；设计实验时，检查每个实验是否对应一条主张；定位贡献时，检查四个阶段是否指向同一件事。
5. **在关键决策点停下来判断**（见第四节）：选哪个问题下注、与已有工作撞车怎么办、原型失败后修还是换。
6. **卡住时看升级样板**：真实论文在同样的位置是怎样往前走的。

阶段之间可以交叉、回退：方法验证失败时，可能要回到问题，甚至回到现状。这与规则层的"共同迭代问题与方法"一致。

## 二、用法 B：评判和优化已有的 idea 或 section

1. 定类型和目标档次。档次只是细节，不必过多关注：T-RO、IJRR 为第一档；TMECH、TCYB 等为第二档；RA-L、ICRA 为第三档。**已发表的论文都是正例**：它们是"贡献多大才够某个档次"的参照，不能拿一档期刊的加分项去否定已被会议接收的工作；但这不豁免技术核查，发现的具体缺口照样记录。
2. **按顺序判断三件事**，前一件不成立时，后一件不能补偿：
   1. **核心是否成立**：问题真实吗？核心保证或主张真的由方法和证据推得出吗（阶段三 C 的第 5 条）？闭环通吗？
   2. **证据是否充分**：每条主张有没有匹配其类型的证据（阶段四第 10 步）？对照能否排除关键的替代解释？
   3. **够哪个档次**：在前两件成立的基础上，按加分项和样本的证据配置判断。技术错误和"缺少加分项"性质不同，不要混在一起计数。
3. 对每个相关阶段逐条判断，状态用"满足 / 部分满足 / 不满足 / 不适用 / 无法判定（材料不足）"，写出依据。加分项中包含几件事的，分开判断。
4. 对每个"不满足"，用诊断表给出改法，并参照该阶段"怎么做"里对应的招式和升级样板。改法写研究上怎样改，不写措辞怎样改。

**输出格式**

```
类型：……        目标档次：……
核心是否成立：是 / 否，问题在 [哪里]
证据是否充分：是 / 否，缺 [哪条主张的哪类证据]
档次判断：……（置信度）
| 阶段 | 条目 | 判断 | 依据 | 改法（对照） |
跨阶段闭环：通 / 断在 [哪一环]
若要提升到 [更高档次]，研究上优先补：1. …… 2. ……
```

自测记录见 [evals/2026-10-29_stages_self_check.md](../../evals/2026-10-29_stages_self_check.md)。

## 三、跨阶段闭环（所有样本共有的核心特征）

> **问题**里写出的机制原因 = **方法**改动的位置 = **实验**检验的主张 = **贡献**陈述的能力或认识

| 例子 | 问题中的机制原因 | 方法改动的位置 | 实验检验的主张 | 贡献陈述的能力或认识 |
|---|---|---|---|---|
| R13 | 能量函数的形状同时决定精度和收敛 | 能量函数的表示与参数约束 | 同一训练目标下只换表示，比较一致性；再比较复现误差 | 稳定且精确的示教学习 |
| L02 | 不稳定交互中，只学力会失效 | 力、刚度、阻尼同步学习 | 三种扰动分别检验三个部件；只学前馈的对照失败 | 处理不稳定交互的类人适应 |
| L10 | 可操控性与接触稳定性此消彼长 | 人的力决定参考，学习补偿环境扰动 | 同时测路径误差和人的施力 | 同时保证二者 |
| T04 | 精度与柔顺在反馈控制中冲突 | 精确的前馈模型承担精度 | 增益降两个数量级后的跟踪精度 | 同时柔顺且精确 |
| K16 | 刚度增大时向系统注入能量，经典分析失效 | 稳定性分析所用的函数（加交叉项），条件只依赖参数曲线 | 在对手的仿真上比较；扰动下对手退回恒刚度；真实曲线能否通过检验 | 执行前就能验证任一变阻抗曲线的稳定性 |

**检查方法**：用一句话分别写出四格。只要有一格写不出，或者两格说的不是同一件事，闭环就断了，先修闭环。普通论文最常见的断法是：问题写"前人没考虑 X"，方法是"模块 A + 模块 B"，实验与固定参数比总误差，贡献写"提出一个框架"。

**四格都通，还要回到任务检查一次**：方法保留下来的能力，是否仍足以完成原任务？一个过于保守的机制也能填满四格（"禁止变化，所以稳定"），却没有贡献。K16 用真实的刚度曲线检验条件不会拒绝合理的方案，回答的正是这个问题 [K16 p.5–6]。

## 四、研究推进中的关键决策（跨阶段）

成稿只留下成功的路线，看不到选择、撞车和失败。以下由样本的研究线（前后版本、同组后续论文）与检验中的经验归纳，属于 [推断]。

| 决策点 | 怎样判断 | 详见 | 样本中的依据 |
|---|---|---|---|
| **几个问题都值得做，选哪个** | 每个候选写潜在贡献、最关键的不确定性、最便宜的判别检验、资源依赖；先做能否决整条路线的检验 | 02 第 8 步 | — |
| **与已有工作撞车** | 按模型与假设、保证对象、条件强弱、自由度、确认时机、实验覆盖逐项对照。只是算法名称或模块重合，不退避；实质覆盖了原来的主张，就修正贡献判断，再沿它的前提和失效继续深挖剩下的部分：新的条件、不同形式的保证、效率、解释不一致的结果（规则层的原则）。深挖后仍找不到有分量的剩余，才回到问题阶段换切入点 | 01 第 4 步 | K16 面对已有的能量罐方法，找到了不同形式的保证（事前离线验证，而非运行时监测），并按条件写清何时用哪种 [K16 p.1–2, p.6] |
| **原型失败：修、换还是放弃** | 先分诊：实现有错、实验失真、某一环没起作用、机制无效或太保守、假设不成立、问题价值不足；按诊断决定下一步。事先写好关键假设的放弃条件 | 03 D 第 5 步 | JinT 能量罐 → 同组改为由构造保证；Pol 去掉对角惯量假设 |
| **下一篇做什么** | 每一篇都要能独立成立；下一篇常来自上一篇写下的未解问题或具体失效，或去掉一个假设、从特例推广到一般 | 02 来源④、第 7 步 | L05 → L08；L02 → L07；K16 前作 [15] → K16；A01 → A02 → A03 |
