# 阶段参考层：顶刊研究者在每个阶段怎么做、做到什么程度

本文件夹从真实的顶会顶刊逆向分析而来，目的是让 agent 成为**顶级研究者**：

- **会做**：能和用户一起，从头把一项研究做到顶刊水平，包括看清现状、找到值得做的问题、让方法从问题里长出来、设计能支撑主张的实验、把贡献放在恰当的层次；
- **会判断**：熟练掌握顶会顶刊的标准，能评判一个已有的 idea 或 section，并把它优化到顶刊水平。

写作另有 skill，不在这里。

五个阶段文件与规则层 [workflow/](../../workflow/) 一一对应。规则层写研究流程，本层写顶刊作者在每一步实际怎么做、做到什么程度：

| 文件 | 这一阶段做什么 |
|---|---|
| [01_literature.md](01_literature.md) | 看清最强方法做到哪里、为什么停下，找到真实的缺口 |
| [02_problem.md](02_problem.md) | 找到值得做的问题，并把它定准 |
| [03_method.md](03_method.md) | 让方法从问题里长出来，做到专业完整；含快速验证与迭代 |
| [04_experiments.md](04_experiments.md) | 从主张出发设计实验，让证据支撑主张 |
| [05_contribution.md](05_contribution.md) | 把贡献放在恰当的层次，强度与证据一致 |

每个阶段文件的结构相同：

1. **要回答的问题**；
2. **怎么做**（主体）：顶刊研究者在这一阶段的做法与招式，每一招附真实论文的例子，最后写出这一阶段应当产出什么；
3. **做到什么程度**（尺子）：
   - **底线**：几乎所有已发表的顶会顶刊样本都满足的，并点名例外；
   - **加分**：多数一档期刊样本具备、会议和短文常省略的；
4. **适用条件**：随论文类型、期刊文化的变化；
5. **自检与改进**：诊断表，即"症状 → 没达到哪条 → 怎样改 → 对照"；
6. **升级样板**：真实论文从前版到后版，这一阶段改了什么；
7. **锚点论文**。

## 一、用法 A：做研究（按阶段推进）

1. **定类型**：理论/方法型（贡献是通用的表示、机制或保证），还是应用/问题驱动型（贡献是在具体任务中获得某种能力）。同一项工作只按一种类型推进，避免"四不像"。
2. **每个阶段按"怎么做"推进**，得到该阶段的产出。
3. **每个阶段结束时用尺子自检**：底线必须满足；加分按目标档次争取，以该档样本的中位水平为目标（见第二节的表），不追求"能想到的最完整配置"。不满足的，用诊断表改。研究还在设计阶段时，涉及证据的条款分开记"已设计"和"已完成"，不要因为证据还没做就判定设计不合格。
4. **阶段之间检查闭环**（见第三节）：问题定下后，检查方法的改动是否对准问题里的机制原因；设计实验时，检查每个实验是否对应一条主张；定位贡献时，检查四个阶段是否指向同一件事。
5. **卡住时看升级样板**：真实论文在同样的位置是怎样往前走的。

阶段之间可以交叉、回退：方法验证失败时，可能要回到问题，甚至回到现状。这与规则层的"共同迭代问题与方法"一致。

## 二、用法 B：评判和优化已有的 idea 或 section

**评判的依据是本文件夹已分析过的顶会顶刊样本，不是 AI 自己对"好论文"的印象。** 判断一篇工作够不够某个档次，就把它与该档样本的中位水平逐项对齐：达到中位水平即够；只在该档多数样本都具备的东西上提要求。常见的偏差是把大规模消融、多场景泛化、严格的统计显著性一律当成必要条件；这些在三档和二档样本中几乎都没有，在一档样本中也只有部分论文具备（见下表）。检验中，隐去出处评判的 7 篇里有 3 篇被低估一档或判为未达，没有一篇被高估，原因正是这种加码。

1. **定类型和目标档次。** 一档 T-RO、IJRR；二档 TMECH、TCYB、TNNLS 等；三档 RA-L、ICRA。档次只是细节，不必过多关注。**已发表的论文都是正例。**
2. **选参照样本。** 从下表中目标档次、同一类型的样本里选 2–3 篇，作为这次评判的参照；需要细节时读它们的画像。
3. **逐项对齐中位水平。** 对问题、方法、实验、贡献四项，写出"本工作做到什么"和"参照样本做到什么"。达到或超过中位水平，就算满足这一档；只有该档多数样本都有、而本工作没有的，才算缺口。
4. **再查底线和闭环。** 底线只问"有没有"（有没有对应证据、有没有机制对照），不问"够不够"；"够不够"属于加分项（例如把收益归到某一个部件属于 04 P2，不属于 04 B2）。期刊文化不同时，按各阶段文件中"适用条件"一节判断。
5. **技术疑点单独列出**，不直接当作档次结论。
6. **给改法。** 对每个缺口，用诊断表给出研究上的改法，并参照对应的招式和升级样板。要提升档次时，以上一档样本的中位水平为目标，而不是以"能想到的最完整配置"为目标。

### 各档样本的中位水平（评判时的参照）

以下由本文件夹已分析的样本统计，具体见各画像与 04 的证据配置一览。

| | 三档与会议：RA-L、ICRA、IROS（8 篇：C01、Dyck、A02、L01、JinI、Beb、A03、A01） | 二档：TMECH、TNNLS 等（4 篇：JinT、L06、C03、L09；控制理论期刊 L03、L04 另见适用条件） | 一档：T-RO、IJRR（16 篇，另有 NMI 的 L08、RSS 的 T04） |
|---|---|---|---|
| **问题** | 一个具体的能力缺口；写到"没人做过 X，而 X 关系到 Y"即可（JinI、L01） | 多数写到已有方法为什么做不到（JinT p.3、C03 p.1） | 多数写到机制原因或前提失效；常有"假设 + 期望性质"、两难排序 |
| **方法** | 一个关键改动，完整可执行；继承关系写清 | 一个改动加对最看重性质的定理或分析（JinT、L09、C03） | 改动从瓶颈推出；保证写清对象与条件；不少把已有方法纳入为特例 |
| **对照** | 一种：两端、常见做法或有无机制（Beb、Dyck、JinI、C01） | 两端加 1–2 个竞争方法族或充分调优的控制器（JinT、C03），或理想对照（L09） | 约一半与最接近的方法族比较（R13、T02、T03、T05、T06、L10、Wij、K16）；其余用两端、固定参数、理想对照或去掉机制的版本（L05、T01、Pol、L02、L07、T07） |
| **消融** | 0–1 个（只有 Dyck 有一个内部消融） | 多为参数敏感性或条件设计（JinT、L06），少有逐部件消融 | 约一半样本有逐部件消融（L02、T01、T02、T03、R13、T05、T06、T04）；K16、T07 没有 |
| **场景与泛化** | 一类任务，加一两种扰动或条件 | 几种条件或任务（L06 三种条件，JinT 三类任务） | 多数有几类任务或条件；训练外泛化只在部分样本中出现（T01、T02） |
| **实物与重复** | 实物或模体；单次运行或每种情况约 5 次（C01） | 实物单次运行（JinT）或约 7 次（L06）；L04 只有仿真 | 几乎都有实物（K16 用已发表的真实数据，T06 用标准数据集）；每种条件数次，以成功率为主张时可到 30 次（T01） |
| **统计检验** | 多数没有；应用型与人或重复测量比较时用简单 t 检验（A02、A03） | 没有 | 只在涉及人或随机性时出现（L05、L10、FuR、T02、T05、T06）；K16、T07 等没有 |
| **贡献** | 2–3 条，集中在一个改动 | 2–4 条，多在机制与能力之间 | 多数落在能力层，增量写得精确；短文（K16、T07）也可停在条件或机制层 |

**怎样用这张表**
- 判断"够不够三档"，就看本工作是否达到三档这一列。不要拿一档那一列，更不要拿"表里所有格子"去要求。
- 一档的短文（K16、T07）说明：一档期刊也接收证据精简、只做一件事的工作，前提是那件事本身有分量。
- 这张表反映的是本文件夹的样本，主要在机器人交互控制领域。评判其他领域时，先按同样方式找该领域同档的已发表论文作参照。

**输出格式**

```
类型：……        目标档次：……        参照样本：……（2–3 篇）
对齐结果：问题 / 方法 / 实验 / 贡献 各自 达到 / 未达到 该档中位水平，依据：……
底线：| 阶段 | 条目 | 判断 | 依据 |
跨阶段闭环：通 / 断在 [哪一环]
技术疑点（不计入档次）：……
结论：达到 / 未达到 [档次]；缺口只列该档多数样本都具备的项
若要提升到 [上一档]，以上一档中位水平为目标，研究上优先补：1. …… 2. ……
```

## 三、跨阶段闭环（所有样本共有的核心特征）

> **问题**里写出的机制原因 = **方法**改动的位置 = **实验**检验的主张 = **贡献**陈述的能力

| 例子 | 问题中的机制原因 | 方法改动的位置 | 实验检验的主张 | 贡献陈述的能力 |
|---|---|---|---|---|
| R13 | 能量函数的形状同时决定精度和收敛 | 能量函数的表示与参数约束 | 同一训练目标下只换表示，比较一致性；再比较复现误差 | 稳定且精确的示教学习 |
| L02 | 不稳定交互中，只学力会失效 | 力、刚度、阻尼同步学习 | 三种扰动分别检验三个部件；只学前馈的对照失败 | 处理不稳定交互的类人适应 |
| L10 | 可操控性与接触稳定性此消彼长 | 人的力决定参考，学习补偿环境扰动 | 同时测路径误差和人的施力 | 同时保证二者 |
| T04 | 精度与柔顺在反馈控制中冲突 | 精确的前馈模型承担精度 | 增益降两个数量级后的跟踪精度 | 同时柔顺且精确 |
| K16 | 刚度增大时向系统注入能量，经典分析失效 | 稳定性分析所用的函数（加交叉项），条件只依赖参数曲线 | 在对手的仿真上比较；真实曲线能否通过检验 | 执行前就能验证变阻抗曲线的稳定性 |

**检查方法**：用一句话分别写出四格。只要有一格写不出，或者两格说的不是同一件事，闭环就断了，先修闭环。普通论文最常见的断法是：问题写"前人没考虑 X"，方法是"模块 A + 模块 B"，实验与固定参数比总误差，贡献写"提出一个框架"。
