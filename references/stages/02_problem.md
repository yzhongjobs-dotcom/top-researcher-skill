# 阶段二参考：顶刊的研究问题怎样定

> **样例（2026-10-29）**：依据 9 篇已核对原文的论文写成，供用户确认方向，之后随批量阅读扩充和修正。对应规则层 [workflow/02_problem.md](../../workflow/02_problem.md)。页码为各论文 PDF 页码。[原文] 为作者明说，[推断] 为分析者判断。
>
> **通用性**：本文件是通用 skill 的一部分。每条判断先给领域无关的表述和"通用改写"，具体论文只作例证。当前样本集中在机器人交互控制和医疗接触，凡可能只在这一领域成立的结论，都单独注明；扩大样本时会有意加入其他领域的顶刊。
>
> 样本：R13 Jin T-RO2023（理论/方法型）；Pollayil T-RO2023（理论/方法型）；Wijayarathne T-RO2023（方法型，医疗动机）；Jin ICRA2022 → TMECH2023（同一研究线）；Dyck RA-L2022（应用驱动的方法贡献）；Fu TIM2024 → Fu T-RO2025（同一研究线，医疗）；Beber ICRA2024（医疗）。

## 一、顶刊实际怎么做（六条判断）

### 判断 1：问题落在"能力差距 + 差距的机制原因"上，而不是"别人没做 X"

顶刊的问题陈述包含三件事：
- 任务需要什么能力；
- 最强已有方法给不了的那一部分；
- **为什么**给不了，即卡在哪个表示、假设或结构上。

第三件事是关键：它让问题变得可检验，方法也有了方向。

| 论文 | 能力差距 | 机制原因（作者怎样写） |
|---|---|---|
| R13 | 稳定的示教学习要同时保证全局收敛和复现精度 | 两种主流稳定 ADS 学习范式都要求轨迹沿能量函数下降，所以**能量函数的形状同时决定精度和收敛**：二次型太僵硬，灵活的数据驱动能量函数会产生伪极小 [原文 p.4] |
| Jin TMECH2023 | 在线调整精度—柔顺的权衡模式 | 写出经典 MPC-VIC 的模型、代价和 Riccati 解的形式，指出两点：代价权衡的是误差与 ω，而 ω 不等于柔顺度；一加约束，解的形式就不成立，阻抗参数也恢复不出来 [原文 p.3] |
| Pollayil | 在不做惯量整形、没有力/力矩传感器的机器人上在线选择刚度和阻尼 | 已有阻抗规划方法默认能做惯量整形，而惯量整形需要精确的力反馈；不做整形时惯量耦合，单自由度的设计方法失效 [原文 p.1, p.3–4] |
| Wijayarathne | 在软接触上同时跟踪运动轨迹和力轨迹 | 带接触的轨迹优化已经能自动发现接触序列，但优化出的接触力**只用于探索、没有用于控制**；带完整接触动力学的约束轨迹优化又难以在线求解 [原文 p.2] |
| Dyck | 在任意曲面上被动地产生接触力，并贴合法向扫描 | 前馈力方案在失去接触时不无源；解析曲面方法处理不了网格；预计算轨迹无法支持手把手模式 [原文 p.1–2] |

**普通论文常见做法**：Fu TIM2024 的差距只有一句，说最接近的优化方法"未考虑环境变形和闭环力控" [原文 p.2]。它没有说明这些方法为什么做不到，也没有写出它们的表述去指出哪里出问题。读者无法判断这到底是真缺口，还是只是没人做过。

**同一研究线的对照最能说明这一条**：Jin 的 ICRA 版把问题写成两条功能（加阻抗约束、加位置和速度约束）[ICRA p.2]；TMECH 版用的是同一个模型，却把问题改写成上表的机制诊断 [TMECH p.3]。期刊版在问题这一步补上的，正是"为什么做不到"。

**通用改写**
- 普通写法："现有方法 A、B 没有考虑 X，因此本文研究考虑 X 的方法。"
- 改写步骤：①写出任务需要的能力 C，尽量可测量；②找出最强方法 A 的核心表述 F，即它的模型、表示、假设或解的结构；③找出 F 中与 C 冲突的那一处，说明在什么条件 S 下冲突、为什么冲突；④用一个最小例子或推导展示这种冲突确实发生。
- 顶刊形态："任务需要 C。A 通过 F 已经做到了 C 的一部分；但 F 依赖 H（或把关键量 Q 藏在 R 中），所以在 S 条件下无法做到 C。"
- 写不出第③步时，说明问题还停在"没人做过"的层次：要么继续追问 X 为什么难，要么检查 X 是否真的影响任务。

### 判断 2：两难问题要给两端排序，把一端变成硬保证或约束，另一端变成优化目标

| 论文 | 两端 | 怎样排序 |
|---|---|---|
| R13 | 唯一极小（收敛）与灵活性（精度） | [原文 p.4] 唯一极小关系到安全，所以更重要；问题定为"保证唯一极小的前提下，尽量提高灵活性" |
| Pollayil | 低阻抗（对意外接触鲁棒）与高阻抗（跟踪精度） | [原文 p.4–5] 跟踪误差的上界 b_i 作为约束，在这个约束下让阻抗最小 |
| Jin TMECH | 精度与柔顺 | 代价函数里两者加权；但用阻抗参数的上下界把**两端的极限**变成硬约束，k_max 决定最差柔顺度，k_min 决定最差精度 [原文 p.4–5, p.11] |
| Dyck | 接触力与失去接触时的安全 | 无源性由结构保证，即只用经典阻抗；力的大小交给负的设定值，放弃对力的精确跟踪 |

[推断] 排序决定了方法要"由构造保证"哪一端，也决定了实验要证明什么：保证的那一端用定理或结构说明，优化的那一端用对比实验说明。只在代价函数里给两项加权、却不交代哪端优先，是常见的弱写法。例如 Fu TIM2024 把力误差和"刚度靠近 K_min"加权放进同一个代价 [原文 p.3, Eq.(10)]，没有说明在什么情况下牺牲哪一端。

**通用改写**
- 普通写法："本文希望同时提高 P 和 Q。"（再在代价函数里给两项加权）
- 改写步骤：①问哪一端一旦失败就不可接受（安全、正确性、可行性）；②把这一端写成约束或结构上的保证，另一端写成目标；③写出排序的理由；④想清楚保证的那一端用什么证明（定理或结构），优化的那一端用什么证明（对比实验）。
- 顶刊形态："在保证 P（理由）的前提下，让 Q 尽可能好。"
- 如果两端确实同等重要、可以互换，就如实写成权衡，并说明怎样选择权衡点。

### 判断 3：问题的边界由显式假设划定，并且每个假设都给出理由

- **Pollayil**：用两条假设把问题变得可解。Assumption 1：惯量在两次规划之间近似不变；Assumption 2：外部扰动是短时冲击。两条都写了适用条件，例如"机器人速度不高、规划频率较高"；并用 Remark 2 说明冲击响应等价于某个初值下的自由响应，从而把鲁棒优化转成可解的问题 [原文 p.5]。
- **R13**：把任务限定为目标静止的目标导向运动，并用"任何任务都可以分解为若干目标导向运动"来为这一限定辩护 [原文 p.3]。
- **Wijayarathne**：在讨论里承认，接触模型只在局部有效，力的大小也保持在线性区间内 [原文 p.14]。

[推断] 顶刊不追求"问题越大越好"。它把问题限定在能严格处理的范围内，同时说明这个范围覆盖了哪些实际情况。这正对应规则层"问题大小合适"的要求。

**通用改写**
- 普通写法："本文方法适用于 [某个大类任务]。"
- 改写步骤：①列出方法实际依赖的条件；②把其中不显然的写成显式假设；③每个假设写出它覆盖的实际情况，以及不成立时会怎样；④检查这些假设是否正好让问题可以严格处理。
- 顶刊形态："假设 1（……），在 [条件] 下合理；在此假设下，问题可以转化为 ……。"

### 判断 4：重要性来自"不解决会怎样失败"，而且失败要被展示出来

- **R13**：在方法之前用两张二维图展示失败。直接回归得到的 ADS 会收敛到伪吸引子或发散（Fig.2）；二次能量函数让轨迹严重变形，而有局部极小的能量函数会把轨迹困住（Fig.3）[原文 p.3–4]。
- **Pollayil**：用 ANYmal 展示两端都会失败（Fig.2）：低阻抗时受到外力就摔倒，高阻抗时接触环境会失去支撑 [原文 p.4]。
- **Dyck**：在实验里展示前馈力方案失去接触后产生冲击 [原文 p.7–8]。

**普通论文常见做法**：只用应用需求说明重要性，例如"临床需要合适的接触力"[Fu TIM p.1]，不展示已有方法在什么条件下会失败。

**通用改写**
- 普通写法："[应用] 很重要，需要 [能力]。"
- 改写步骤：①找出不解决这个问题时最典型的失败；②在方法出现之前，用最小例子、简化实验或文献中的结果把这个失败展示出来；③让失败对应到判断 1 中诊断出的机制。
- 顶刊形态："如图 X 所示，现有做法在 S 条件下会出现 [具体失败]，原因是 [机制]。"

### 判断 5：先准确承认强 prior 做到了什么，再说剩下什么

- **R13**：承认 WSAQF、FDM、ICNN **已经**保证唯一极小，再分别指出它们的灵活性卡在哪里：类二次型、拓扑约束（生成不了螺旋）、凸性 [原文 p.2–3]。
- **Wijayarathne**：先说接触感知轨迹优化在足式运动和灵巧操作上"效果出色"，再指出接触力没有用于控制 [原文 p.2]。
- **Pollayil**：在长篇综述之后，只用三条明确的新意来定位自己：不需要力/力矩传感器；建立在成熟理论上、与具体系统无关；按最坏情况设计 [原文 p.4]。

[推断] 这样写的好处是缺口不会被强 prior 否定：剩下的部分是准确的，审稿人无法用"某某已经做过"来反驳。这条支持规则层"遇到强 prior 不避开，追问剩余痛点"，也给出了顶刊上的标准形态。

**通用改写**
- 普通写法："已有方法 A、B、C 存在不足。"
- 改写步骤：①找出已经解决了最多问题的那一两篇；②准确写出它们已经做到的部分，包括它们能保证什么；③在此基础上写出剩下的、它们做不到的部分；④检查这个剩余缺口能否被它们直接否定。
- 顶刊形态："A 已经保证了 P，并在 S 下表现很好；但 A 的 [具体结构] 使它无法 ……。"

### 判断 6：会议版到期刊版，问题常见三种升级方式

| 方式 | 例子 | 说明 |
|---|---|---|
| 去掉一个限制性假设 | Pollayil：会议版 [13] 只处理对角惯量，期刊版推广到非对角惯量，并把会议版方法作为特例包含进来 [原文 p.2] | 问题本身不变，适用范围变大 |
| 加上一个真实条件 | Wijayarathne：会议版 [45] 只在静止平台上验证，期刊版加入周期运动的平台，并实现在线 MPC [原文 p.2–3] | 同一问题，条件更难、更真实 |
| 从功能提升到能力，并写出机制诊断 | Jin：从"受约束 VIC 怎样求解"提升到"自适应的精度—柔顺权衡"，并给出对手的方程诊断 [ICRA p.2; TMECH p.1–4] | 同一矛盾，表述层次更高 |

**要警惕的第四种**：靠加模块扩大问题。Fu T-RO2025 在 TIM2024 的 QP 变阻抗上加了遥操作和 shared control，问题扩大为"降低操作者负担"[原文 p.3]。但 NASA-TLX 结果显示，IC-S 和 VIC-S 两种模式在 6 项指标上都没有显著差异 [原文 p.17, Fig.14]。也就是说，负担的下降来自 shared control，而不是本文核心的变阻抗。问题扩大后，核心贡献反而更难归因。[推断] 这篇能进 T-RO，靠的是系统层面的证据（12 名用户、全局无源性证明），而不是问题定得深。

**通用改写**（扩展自己的前作时）
- 先问增量属于哪一种：去掉了哪个假设、加了哪个真实条件，还是给出了机制诊断？三者都不是，只是加了模块，就要先回答"新模块带来了哪项能力，怎样证明是它带来的"。
- 期刊版要写明会议版是哪篇，以及相对它做了哪几处扩展。

## 二、作者怎样决定（选项、取舍与理由）

| 决策 | 常见选项 | 顶刊样本的选择与理由 |
|---|---|---|
| 问题定在哪一层 | 功能、算法细节、能力、表示 | 定在能力层，再落到一个具体的表示或结构瓶颈：R13 落到能量函数的表示，Jin TMECH 落到阻抗模型的输入形式，Dyck 落到任务坐标 |
| 两难怎样处理 | 两端并重 / 只做一端 / 排序 | 排序，理由写进正文（安全、可行性）。R13、Pollayil |
| 范围限多大 | 尽量通用 / 用假设收窄 | 用显式假设收窄，并说明覆盖的实际情况。Pollayil 的 Assumption 1–2 |
| 面对强 prior | 绕开 / 缩题 / 承认后找剩余 | 承认后找剩余，剩余部分要能用对手的表述或实验看出来。R13、Wijayarathne |

## 三、变化范围

- **理论/方法型**（R13、Pollayil）：问题写成一个通用的表述，例如"一类函数""一类控制器"，应用只作演示；差距用表示或假设来定义。
- **应用驱动的方法贡献**（Dyck、Wijayarathne）：问题从任务需求出发，但顶刊会把它转成一个精确的控制或优化表述（任务坐标、带接触模型的轨迹优化），差距仍然落在机制上。
- **系统/应用型**（Fu T-RO2025）：问题是系统能力（遥操作 + 力控 + 负担），差距用多项需求的组合来定义；这类论文对"每项能力由哪个部件带来"的归因要求更高。
- **期刊文化**：T-RO 样本都写出了机制原因；TMECH 样本（Jin）在期刊版也写出了机制原因；TIM 样本（Fu）停留在"没考虑 X"。ICRA 样本里，Jin 停留在功能层，Beber 则明确写出了相对于前作的两处差异 [原文 Beber p.4]。[推断] 会议短文也可以把问题写准，差别不在篇幅。样本还少，期刊之间的差别只作观察，不当规律。

## 四、好与普通的差别（问题这一步）

| 维度 | 顶刊 | 普通 |
|---|---|---|
| 差距怎样表述 | 能力差距 + 机制原因，能用对手的表述或实验看出来 | "前人没考虑 X" |
| 两难 | 两端排序，一端硬保证 | 两端加权，不交代优先级 |
| 重要性 | 展示不解决会怎样失败 | 只引用应用需求 |
| 强 prior | 先准确承认，再说剩余 | 笼统归类，或不提最接近的工作 |
| 范围 | 显式假设，并说明覆盖什么 | 默认适用于"医疗接触任务"等大范围 |
| 扩展时 | 去假设、加真实条件、诊断机制 | 加模块扩大问题，核心贡献难以归因 |

## 五、锚点论文（定问题时对照）

| 类型 | 锚点 | 对照时看什么 |
|---|---|---|
| 理论/方法型，两难 | R13 T-RO2023 | 怎样把两难排序成"硬保证 + 优化"，怎样把机制原因落到一个表示上（p.3–4） |
| 理论/方法型，放宽假设 | Pollayil T-RO2023 | 怎样用显式假设把问题变得可解，怎样写会议版到期刊版的推广（p.2–5） |

## 六、用于自己的工作

**定问题时逐条自问：**
1. 我能不能用一句话写出"最强方法为什么做不到"？这句话指向的是一个表示、假设还是结构？如果只能写出"它没考虑 X"，就继续追问 X 为什么难，或者 X 是否真的影响任务。
2. 这是不是一个两难？如果是，哪一端必须硬保证，理由是什么？另一端怎样衡量？
3. 我的范围靠哪些假设划定？每个假设覆盖了哪些实际情况，又排除了什么？
4. 我能不能在方法出来之前，用一个最小的例子或实验展示"不解决会怎样失败"？
5. 我有没有准确写出最强 prior 已经做到的部分？剩下的缺口会不会被它直接否定？
6. 如果我在扩展自己的前作：是在去掉假设、加真实条件、诊断机制，还是只是在加模块？

**agent 容易犯的错（与规则层的"AI 犯过的错"对应）：**
- 把"没人在这个场景里用过方法 Y"当作研究问题。这是功能层的差距，到不了顶刊。
- 两端都想要，于是在代价函数里加权了事，却不交代优先级，也不说明怎样证明。
- 用加模块的办法把问题做大，到最后说不清核心贡献带来了哪项能力。

**对规则层的作用（P4 时统一给用户看）**：
- 支持 workflow/02 的判断标准与"遇到强 prior 不避开"；
- 建议在"可借鉴的做法"中补两条：两难问题要给两端排序，把一端变成硬保证或约束（判断 2）；差距要写出机制原因，而不只是"没人做过"（判断 1）。
