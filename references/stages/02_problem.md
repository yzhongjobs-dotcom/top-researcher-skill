# 阶段二参考：顶刊的研究问题怎样定

> 对应规则层 [workflow/02_problem.md](../../workflow/02_problem.md)。本文件写顶会顶刊在"定问题"这一步的**共性做法（即标准）**，再写随论文类型、期刊变化的**适用条件**。每条判断先给领域无关的表述，再给"通用改写"和论文例证。例证编号见 [01_literature.md](01_literature.md) 开头的表格；页码为各论文 PDF 页码。

## 一、顶刊共性（标准）

### 1. 问题 = 能力差距 + 差距的机制原因

**通用表述**：问题陈述要包含三件事：任务需要什么能力；最强方法给不了的那一部分；**为什么**给不了，即卡在哪个表示、假设、结构或信息上。第三件事让问题可检验，也给方法指明方向。

**例证**：
- R13：两种主流范式都要求沿能量函数下降，所以能量函数的形状同时决定精度和收敛；二次型太僵硬，灵活的数据驱动能量函数会产生伪极小 [R13 p.4]。
- JinT：写出经典 MPC 变阻抗的模型、代价和解的形式，指出代价权衡的量不等于柔顺度，一加约束解的形式就不成立 [JinT p.3]。对照它的会议版 Jin ICRA2022，问题只写成两条功能（加阻抗约束、加状态约束）[Jin ICRA p.2]。
- C03：已有实现的失效机制（内环动力学被激发）就是问题的机制原因 [C03 p.1]。
- Wij：接触力只用于探索、没有用于控制；带完整接触动力学的约束优化难以在线求解 [Wij p.2]。

**通用改写**
- 普通写法："现有方法没有考虑 X，因此本文研究考虑 X 的方法。"
- 改写步骤：①写出任务需要的能力 C，尽量可测量；②找出最强方法 A 的核心表述 F（模型、表示、假设或解的结构）；③指出 F 中与 C 冲突的那一处，说明在什么条件下冲突、为什么冲突；④用最小例子或推导展示冲突确实发生。
- 顶刊形态："任务需要 C。A 通过 F 已经做到了 C 的一部分；但 F 依赖 H（或把关键量 Q 藏在 R 中），所以在 S 条件下做不到 C。"
- 第③步写不出时，说明问题还停在"没人做过"的层次：要么继续追问 X 为什么难，要么检查 X 是否真的影响任务。

### 2. 先给核心概念一个可操作的定义，问题才可测量

**通用表述**：问题里涉及的关键能力或概念（稳定、角色、可操控性等），要先给出可操作、可测量的定义；后面的方法和实验都围绕这个定义展开。

**例证**：
- L10 先定义"可操控性"（人引导机器人的难易程度）和"接触稳定性"（存在扰动时保证任务性能的能力），再说明二者冲突 [L10 p.2]；实验相应地测人的驱动功和路径误差 [L10 p.9]。
- L05 先定义"角色"：一个智能体的行为模式，直接对应双方控制输入的比重 [L05 p.2]。
- L02 先给出有限时间意义下"交互稳定"的定义 [L02 p.3]。

**通用改写**：把"希望机器人更安全、更好用"改成"定义指标 M1（例如……）和 M2；本文希望在 M1 不变差的前提下提高 M2"。

### 3. 问题陈述写成"假设 + 期望性质"两张清单

**通用表述**：问题的边界用显式假设划定，每个假设说明它覆盖哪些实际情况；目标写成几条可检验的性质，每条后面都要有对应的方法部件和证据。

**例证**：
- C01 列出三条假设（任务动力学已知且可随时求值、连续、只有一个稳定平衡点）和三条期望性质（保持无源、沿任务方向运动且只在其他方向耗能、阻抗可调）[C01 p.2]。
- Pol 用两条假设（两次规划之间惯量近似不变、扰动为短时冲击）把鲁棒优化变得可解，并写明适用条件（速度不高、规划频率较高）[Pol p.5]。
- R13 把任务限定为目标静止的运动，并说明多数任务可以分解为若干这样的运动 [R13 p.3]。

**通用改写**：
- 普通写法："本文方法适用于 [某个大类任务]。"
- 改写步骤：①列出方法实际依赖的条件；②把不显然的写成显式假设；③每个假设写出它覆盖什么、不成立时会怎样；④列出 2–4 条期望性质，每条都能被检验。
- 顶刊形态："假设 1（……），在 [条件] 下合理。目标：性质 P1（……）、P2（……）。"

### 4. 两难问题有三种顶刊处理形态，选哪种都要说明理由

**通用表述**：两个都想要的性质此消彼长时，顶刊不在两端之间随意加权，而是选择以下三种形态之一，并写明理由：
1. **排序**：一端作为硬保证或约束，另一端作为优化目标。R13 把唯一极小作为保证，理由是它关系到安全 [R13 p.4]；Pol 把跟踪误差上界作为约束，在约束下让阻抗最小 [Pol p.4–5]；JinT 用阻抗参数的上下界给两端设定极限 [JinT p.4–5]。
2. **转移负担**：把一端的负担交给另一个部件，从而在原来冲突的维度上同时满足两端。T04 让精确的前馈模型承担精度，使反馈增益可以降低以获得柔顺 [T04 p.1]。
3. **在两端之间自适应，或把两端都纳入为特例**：L05 让机器人在"主导"和"跟随"之间连续调整角色 [L05 p.1–2]；T03 证明域随机化和域自适应都是本文框架的特例 [T03 p.8]；L10 让一部分负责人的意图、一部分负责环境扰动 [L10 p.3–4]。

**通用改写**：
- 普通写法："本文希望同时提高 P 和 Q。"（然后在代价函数里加权）
- 改写步骤：①问哪一端失败就不可接受，或者能否把一端的负担转给另一个部件，或者能否在两端之间按情况切换；②选定形态并写出理由；③保证的一端用定理或结构证明，优化的一端用对比实验证明。
- 顶刊形态："在保证 P（理由）的前提下让 Q 尽可能好"，或"让部件 X 承担 P，从而使 Q 不再受限"，或"按 [条件] 在 P 与 Q 之间连续调整"。

### 5. 重要性来自"不解决会怎样"，并用证据展示出来

**通用表述**：重要性的来源要具体，常见四种：
1. **存在性证明**：人或其他系统已经能做到，机器人不能（L01、L02、L07：人能稳定完成不稳定的工具使用 [L02 p.1]；C02：生物系统靠低增益、可变阻抗 [C02 p.2]）；
2. **在方法之前展示失败**：R13 用二维例子展示伪吸引子和轨迹变形 [R13 p.3–4]；Pol 用 ANYmal 展示高、低阻抗两端都会失败 [Pol p.4]；
3. **领域内的危害与需求**（应用型）：AAA 破裂死亡率、筛查需要可重复性 [A01 p.1]；
4. **从任务结构推出需求**：T03 中基元由缺少几何信息的符号规划器排序，所以每个基元必须对物理参数鲁棒 [T03 p.1]。

**通用改写**：
- 普通写法："[应用] 很重要，需要 [能力]。"
- 顶刊形态："如 [图/例] 所示，现有做法在 S 条件下会出现 [具体失败]，原因是 [机制]"；或"人/生物系统已经能 ……，机器人还不能。"

### 6. 问题的大小：一次推进一步，起点常是前作的具体失效或未解问题

**通用表述**：顶刊不追求"问题越大越好"。常见的推进方式是：从前作的具体失效或未解问题出发，一次只解决一个；或者去掉前作的一个限制性假设，或者加入一个更真实的条件。

**例证**：
- L01 → L02 → L07：1 自由度原型 → 理论加多自由度 → 在前作上只加轨迹自适应，起因是前作在障碍处力过大 [L07 p.1]；
- L05 → L08：前作承认均衡是否存在未知，下一篇证明了它 [L05 p.9；L08 p.6]；
- Pol：去掉"惯量对角"的假设 [Pol p.2]；Wij：从静止平台扩展到周期运动的平台，并实现在线运行 [Wij p.2–3]；
- A 序列：先做出整个流程（A01），再分别深挖探头方向（A02）、物体移动（A03）。

**要警惕的扩题方式**：靠加模块把问题做大。例如 Fu T-RO2025 在 QP 变阻抗上加了遥操作和共享控制，问题扩大为"降低操作者负担"，但负担的下降来自共享控制，而不是核心的变阻抗：IC-S 与 VIC-S 在 6 项 NASA-TLX 指标上都没有显著差异 [Fu T-RO p.17]。

## 二、作者怎样决定

| 决策 | 常见选项 | 顶刊样本的选择与理由 |
|---|---|---|
| 问题定在哪一层 | 功能 / 算法细节 / 能力 | 能力层，再落到一个具体的表示、假设或结构瓶颈（共性 1） |
| 概念怎样落地 | 直接用日常词 / 先给定义 | 先给可测量的定义（共性 2） |
| 范围多大 | 尽量通用 / 用假设收窄 | 用显式假设收窄，并说明覆盖什么（共性 3） |
| 两难怎样处理 | 加权 / 排序 / 转移负担 / 自适应或统一 | 后三种之一，写明理由（共性 4） |
| 下一步做什么 | 换题 / 加模块 / 解决前作的具体失效 | 解决前作的具体失效或未解问题（共性 6） |

## 三、适用条件（随类型与期刊的变化）

- **理论/方法型**（R13、Pol、C03、T03）：问题写成一个通用表述的局限（一类函数、一类控制器），应用只作演示。
- **应用/问题驱动型**（A 序列、L05、L10）：问题从任务或临床流程出发，但顶刊仍会把它转成精确的控制或优化表述，并定义可测量的能力。
- **面向广泛读者的期刊**（L08）：问题写在范式层面（"人机交互缺少系统方法"），再落到一个可证明的基本问题（两个相连的智能体能否在互相辨识的同时保持稳定）[L08 p.2–3, p.11]。
- **控制理论期刊**（L03、L04）：问题常是"放宽一个前提"（不需要重复、不需要已知环境），并主动论证为什么这件事更难 [L04 p.3]。
- **会议到期刊**：JinT 对照其 ICRA 版，期刊版补上的正是机制诊断（共性 1）。

## 四、与普通论文的差别（辅助）

| 维度 | 顶刊 | 普通 |
|---|---|---|
| 差距 | 能力差距 + 机制原因 | "前人没考虑 X" |
| 概念 | 先给可测量的定义 | 用日常词描述目标 |
| 两难 | 排序、转移负担或自适应，写明理由 | 加权，不说明优先级 |
| 重要性 | 展示失败或给出存在性证明 | 只引用应用需求 |
| 扩展 | 解决前作的具体失效 | 加模块把问题做大 |

## 五、锚点论文（定问题时对照）

| 类型 | 锚点 | 对照时看什么 |
|---|---|---|
| 理论/方法型，两难 | R13 T-RO2023 | 怎样把两难排序，怎样把机制原因落到一个表示上（p.3–4） |
| 理论/方法型，放宽假设 | Pol T-RO2023 | 怎样用显式假设把问题变得可解，怎样写会议版到期刊版的推广（p.2–5） |
| 应用/问题驱动型 | L10 Xing T-RO2023 | 怎样定义两种能力并说明二者冲突（p.2） |
| 研究线延续 | L05 → L08 | 前作局限中的未解问题怎样成为下一篇的核心 |

## 六、用于自己的工作

**定问题时逐条自问：**
1. 我能不能用一句话写出"最强方法为什么做不到"？这句话指向的是一个表示、假设、结构还是信息？
2. 关键概念有没有可测量的定义？
3. 我的范围靠哪些假设划定？每个假设覆盖什么、排除什么？目标性质有哪几条，每条怎样检验？
4. 如果是两难，我选哪种形态（排序、转移负担、自适应），理由是什么？
5. 在方法出来之前，我能不能展示"不解决会怎样失败"，或者给出存在性证明？
6. 这一步是在解决前作或领域里的一个具体失效，还是只是在加模块？

**agent 容易犯的错**（对应规则层的"AI 犯过的错"）：
- 把"这个场景里没人用过方法 Y"当作研究问题（功能层的差距，不是能力差距）。
- 为了让某个算法能赢而缩题，或者反过来不断加模块扩题，最后说不清核心贡献带来了哪项能力。
- 两难问题在代价函数里加权了事，不说明优先级，也不说明怎样证明。
