## 一、顶刊共性（标准）

### 1. 按"每条路线做到什么、依赖什么前提、在什么条件下失效、为什么"来组织，而不是按年代或算法名罗列

**通用表述**：现状的每一组工作都要写清四件事：能力（做到了什么）、前提（依赖什么假设、信息或条件）、失效（在什么条件下不行）、原因（为什么不行）。读者读完现状，应该能自己推出缺口在哪里。

**例证**：
- C03 对三种已有阻抗实现逐一写出失效机制：基于动力学的实现对模型误差敏感；基于位置的实现中，模型误差会激发本应隐藏的内环动力学；折中方案除非内环与期望阻抗一致，否则仍不准 [C03 p.1]。
- L04 按"前提"层层排除：被动阻抗过于保守 → 启发式变阻抗难推广 → 迭代学习需要重复 → LQR 需要已知环境 [L04 p.2–3]。
- T03 逐条写出权衡：鲁棒控制保守，自适应 MPC 太慢，域随机化泛化好但次优，域自适应最优但不泛化，显式自适应需要精确辨识 [T03 p.1–2]。
- T02 把三类方法的失效条件写完后，用一段总结并列三者 [T02 p.1–2]。
- Pol 指出已有阻抗规划默认能做惯量整形，而惯量整形需要精确的力反馈 [Pol p.1, p.3]。

### 2. 用一个统一的视角把各条路线排在同一维度上，缺口自然显现

**通用表述**：找到一个能同时解释多条路线局限的维度（一个概念框架、一个两难、一个共同依赖的部件），让每条路线的不足都落在这个维度上。

**例证**：
- T01 用"信息域与能量域"统一三条路线：基于模型的方法在能量域但贵；统计启发法依赖示教方差；学习方法只在信息域，没有显式阻抗 [T01 p.1–2]。
- R13 指出两种主流稳定学习范式都要求轨迹沿能量函数下降，所以能量函数的形状同时决定精度和收敛 [R13 p.4]。
- T03 用"泛化 vs 最优"统一域随机化和域自适应 [T03 p.2]。
- C01 用"开环执行 DS"统一指出两个缺点：不无源，对物理扰动无反应 [C01 p.1]。

### 3. 对最强、最接近的工作：先准确承认它做到了什么，再写剩下什么；对概念最相近的方法专门写机制区别

**通用表述**：最接近的工作不能笼统归类。要写出它已经做到的部分（包括它能保证什么），再写剩余的、它确实做不到的部分；对和本文概念最像的方法，要写到机制层面的区别，并说明这个区别换来了什么。

**例证**：
- R13 先承认 WSAQF、FDM、ICNN 已经保证唯一极小，再分别指出它们的灵活性卡在类二次型、拓扑约束、凸性上 [R13 p.2–3]。
- Wij 先说接触感知轨迹优化效果出色，再指出优化出的接触力没有用于控制 [Wij p.2]。
- T03 先承认显式自适应在四足行走和手内操作上表现出色，再指出它的前提在接触任务中难以满足 [T03 p.2]。
- C03 专门用一节讲清与扰动观测器方法的区别，并做实验对比 [C03 p.2]；T01 逐项写出与同期最接近工作 ACP 的区别 [T01 p.2]；C01 写出"选择性耗能"与"重新分配动能"的机制区别 [C01 p.1]。

### 4. 缺口的位置有几种常见形态，都比"没人做过"更具体

**通用表述**：顶刊的缺口通常属于以下几种之一；写不出属于哪一种，说明调研还没到位。
1. **已有方法的前提在目标场景中不成立**：L05（已有角色调整需要离散切换或共同目标）[L05 p.1–2]；Pol；T03；L04、L09（需要已知环境、需要重复、需要时不变）[L09 p.1–2]。
2. **两类文献的交叉处**：L10（人机交互文献不考虑环境，机器人—环境文献不考虑人）[L10 p.2]；T01（学习与阻抗控制之间）。
3. **本组前作的具体失效或未解问题**：L07 用 L02 的失效定义问题（障碍处力过大）[L07 p.1]；L05 在局限中承认 Nash 均衡是否存在未知，L08 把它做成核心 [L05 p.9；L08 p.6]。
4. **（应用型）某个流程环节还不能自动完成**：A 序列（采集本身、探头方向、物体移动后的继续扫描）[A01 p.1；A02 p.1；A03 p.1–2]。

### 5. 现状围绕本领域；外域工具在引出方法时介绍，并说明为什么选它

**通用表述**：现状只组织与研究问题直接相关的本领域工作。从外域借来的工具（化工过程控制、随机最优控制、数值张量方法、计算机图形学、生成模型）在提出方法时再介绍，并说明它的哪个性质正好对应本问题的难点。

**例证**：C03 在说明问题之后才介绍内模控制，理由是它的"完美控制"性质和直接的设计方法 [C03 p.1]；C02 说明 PI2 从随机最优控制推出、又能扩展到高维 [C02 p.2]；T03 说明张量列的可分结构使在线检索可行 [T03 p.3]。这与规则层"外域机制只作方法参考，不写进现状"一致。

### 6. 完整性标准：同期工作和本组前作都要写到，并写明本文相对它们的增量

**通用表述**：最接近的工作包括同期出现的工作和作者自己的前作。扩展前作时，要写明前作是哪篇、本文增加了什么。

**例证**：T01 写到同期的 ACP [T01 p.2]；Pol 写明在会议版 [13] 基础上推广到非对角惯量 [Pol p.2]；Wij 写明相对会议版 [45] 的三处扩展 [Wij p.2–3]；T03 写明建立在作者前作 domain contraction 之上 [T03 p.3]；L07 写明初步结果见 [19][20] [L07 p.2]。

## 二、作者怎样决定

| 决策 | 常见选项 | 顶刊样本的选择与理由 |
|---|---|---|
| 怎样分组 | 按年代 / 按算法名 / 按能力与前提 | 按能力与前提，必要时用一个统一视角（共性 1、2） |
| 怎样对待最强工作 | 回避 / 笼统批评 / 承认后找剩余 | 承认后找剩余，剩余部分写到机制层（共性 3） |
| 缺口落在哪里 | 没人做过 / 前提不成立 / 交叉处 / 前作失效 / 流程环节 | 后四种之一（共性 4） |
| 外域工具写在哪里 | 现状里 / 方法里 | 方法里，并说明选它的理由（共性 5） |

## 三、适用条件（随类型与期刊的变化）

- **理论/方法型**（R13、Pol、C03、T03）：现状按表示、假设、解的结构组织，缺口写成"某个表示或假设限制了能力"。
- **应用/问题驱动型**（A 序列、L05、L10）：现状按系统已经能做到流程中的哪一步组织，缺口写成"某个环节还不能自动完成"或"两类交互没有同时考虑"。
- **面向广泛读者的期刊**（L08，NMI）：现状写在范式层面（机器人要么忽视人、要么盲目跟随人），技术细节放到 Methods。
- **控制理论或学习控制期刊**（L03、L04、L09）：现状常是"方法 A 需要前提 P1，方法 B 需要前提 P2"的排除链；缺口多为放宽一个前提。证据要求与机器人顶刊不同，见 [04_experiments.md](04_experiments.md)。
- **短文**（RA-L、ICRA：Dyck、C01）：现状并入引言，篇幅短，但最接近的工作仍要写出机制区别。

## 四、与普通论文的差别（辅助）

普通论文常把最接近的方法笼统地写成"未考虑 X"，既不说明它为什么做不到，也不写它已经做到的部分。例如 Fu TIM2024 对已有优化方法只写了一句"未考虑环境变形和闭环力控"[Fu TIM p.2]。顶刊的写法见共性 1、3。

## 五、锚点论文（调研和写现状时对照）

| 类型 | 锚点 | 对照时看什么 |
|---|---|---|
| 理论/方法型 | C03 Kang TMECH2009 | 怎样对每个已有方法写出失效机制，怎样专门讲清与最相似方法的区别 |
| 理论/方法型 | T03 Xue IJRR | 怎样把多条路线排进一个两难，怎样承认最强方法后找剩余 |
| 方法型，跨范式 | T01 Geiger T-RO2026 | 怎样用一个概念框架组织几条看似无关的路线，怎样写与同期工作的区别 |
| 应用/问题驱动型 | L10 Xing T-RO2023 | 缺口怎样落在两类文献的交叉处 |
| 应用/问题驱动型 | A 序列 | 缺口怎样落在一个流程环节上 |

## 六、用于自己的工作

**调研完成时逐条自问：**
1. 每组工作，我能否写出它的能力、前提、失效条件和原因？只能写出"它不好"的，说明还没读懂。
2. 有没有一个维度（概念框架、两难、共同依赖的部件），能同时解释多条路线的不足？
3. 最接近的工作已经做到了什么？我的缺口会不会被它直接否定？与它概念最像的地方，机制上到底哪里不同？
4. 我的缺口属于哪一种：前提不成立、交叉处、前作失效、流程环节？都不是的话，继续追问。
5. 同期工作和作者自己的前作找全了吗？
6. 外域工具有没有混进现状里？它在方法里出现时，我能否说明它的哪个性质对应本问题的难点？

**通用改写**
- 普通写法："已有方法 A、B、C 存在不足，未考虑 X。"
- 改写步骤：①为每个方法写出能力、前提、失效条件和原因；②找出能同时解释这些失效的维度；③对最接近的工作写出它已经做到的部分；④写出剩余的缺口，说明属于哪种形态。
- 顶刊形态："A 通过 F 做到了 P，但它依赖 H；B 放宽了 H，却在 S 条件下 ……。这些方法的共同局限在于 [统一维度]。本文针对 [剩余缺口]。"

**agent 容易犯的错**（对应规则层的"AI 犯过的错"）：
- 把调研写成"已经有人做过"的证明，看到强 prior 就退；顶刊的做法是承认它做到的，再找剩下的（共性 3）。
- 按算法名判断重合；顶刊按能力和前提比较（共性 1）。
- 稻草人式概括；顶刊对每个方法写出具体的失效机制（共性 1）。
