# 参考资料层

逆向分析的产出，用来细化、校正规则层（[workflow/](../workflow/)）。按需加载：阶段文件会写明遇到什么情况读哪份参考。只引用一层，不互相嵌套引用。

论文类型只粗分两类，作为适用条件的标注，不用来切分文档：

- **理论/方法型**：贡献是通用的新表述、新机制或新保证，应用用于演示。
- **应用/问题驱动型**：贡献是在具体任务中获得某种能力；系统集成类工作通常归入这一类。

所有分析区分 **[原文]**（作者明说，附 PDF 页码/公式/图号）和 **[推断]**（分析者判断）。引用原文只用短句，不复制大段内容。

## 纵向模板：`papers/<编号>_<短名>.md`

1. **基本信息**：题名、作者、期刊/会议、年份、年均引用、论文类型、PDF 路径、实际读过的页码范围。
2. **全文逻辑链**：应用需求 → 核心矛盾 → 已有方法卡在哪里、为什么 → 核心洞见 → 方法 → 证据 → 主张。一段话写清。
3. **逐 section 拆解**：每个 section、每一段在全文中起什么作用（供横向对齐使用，字段与 sections/ 一致）。
4. **关键决策点（5–10 个）**：当时可能的选项 / 实际选择 / 放弃了什么 / 理由（[原文] 或 [推断]）/ 对后文的影响。
5. **承诺—兑现对照**：引言中的每项主张 → 方法中的哪一部分 → 哪个实验或定理兑现。
6. **专业感从哪里来**：形式化方式、符号体系、定理位置、实现细节的详略。
7. **弱点与处理**：审稿人可能攻击什么；作者怎样写局限和边界。
8. **候选规则**：可迁移的经验及其适用条件，标注将补入 workflow 的哪个文件。

## 横向模板：`sections/<section>.md`

覆盖：摘要、引言、related work、问题形式化、方法、理论、实验、讨论与局限、结论。每个文件写：

1. 这个 section 的作用；
2. 逐段的标准写法（常见段落序列及每段功能）；
3. 必须有的要素；
4. 按论文类型、期刊文化的差异；
5. 好论文与普通论文的具体对比（短引 + 页码）；
6. 给 agent 的检查要点与常见错误。
